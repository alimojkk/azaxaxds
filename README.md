# ⚡ X-ui-ali

پنل مدیریت کانفیگ VPN شخصی، مبتنی بر **Xray-core** (پروتکل‌های VLESS / VMess / Trojan روی WebSocket)،
با یک ظاهر تازه، شیشه‌ای و کاملاً اختصاصی (Aurora Glass) — نه کپی هیچ پنل دیگری.

ساخته‌شده برای **نصب فوق‌العاده ساده روی VibeNest**: فورک کنید، لینک ریپازیتوری را بدهید، دیپلوی کنید — تمام!
از همان لحظه اول یک پنل کامل با ساب گرافیکی، QR Code، مدیریت کاربران و... در اختیار دارید.

---

## ✨ چرا X-ui-ali؟

- 🎨 **پنل حرفه‌ای و گرافیکی** — گیج‌های زنده CPU/RAM/دیسک، نمودار مصرف ترافیک روزانه، کارت‌های آماری، فید فعالیت
  زنده و دکمه‌های اکشن سریع، همه با تم اختصاصی شیشه‌ای تیره (Aurora Glass) — کاملاً متفاوت با پنل‌های مشابه
- 🏷️ **ریمارک = دقیقاً همان نامی که شما وارد می‌کنید** — هیچ پسوند یا برندی به کانفیگ‌ها اضافه نمی‌شود
- 🚀 نصب با **Fork + Deploy** روی VibeNest، بدون تنظیم دستی سرور و بدون هیچ مرحله اضافه
- 🖥️ فایل‌های آماده دیپلوی: `docker-compose.yml` و `Dockerfile` برای VibeNest و `install.sh` برای نصب روی VPS شخصی
- ⚡ معماری **تک‌پورت** — پنل و ترافیک VPN هر دو از یک پورت عمومی سرویس رد می‌شوند
- 🔗 پروتکل‌های **VLESS، VMess، Trojan** روی WebSocket + TLS، با امکان **خاموش/روشن سراسری هر پروتکل**
- 📱 **صفحه اشتراک گرافیکی خفن** (تکی و گروهی) با هدر گرادیانی، QR Code برای هر کانفیگ، نوار مصرف ترافیک و دکمه‌های Deep Link برای بازکردن مستقیم در اپ‌ها
- 👤 ساخت/ویرایش/حذف کاربر با چند کلیک یا حتی یک کلیک («کاربر سریع»)، بدون نوشتن کانفیگ
- 📦 **گروه‌های اشتراک** — چند کاربر را در یک لینک ساب واحد ترکیب کنید (مثلاً برای بسته‌های خانوادگی/چندسرویسه)
- 🧑‍🤝‍🧑 **چند-ادمینی** — یک مالک (Owner) پنل می‌تواند ادمین‌های دیگر با دسترسی محدود اضافه کند
- 🗓️ دو استراتژی انقضا برای هر کاربر: **تاریخ ثابت** یا **شروع شمارش از اولین اتصال کاربر**
- 📊 محدودیت ترافیک (GB) و انقضا با غیرفعال‌سازی خودکار + **نمودار مصرف روزانه**
- 🕵️ **گزارش فعالیت (Activity Log)** برای تمام اکشن‌های مهم پنل
- 🖥️ **آمار زنده سرور** (CPU/RAM/دیسک/Uptime) روی داشبورد، بدون هیچ dependency اضافه
- 💾 **پشتیبان‌گیری و بازیابی کامل** پنل با یک فایل JSON (فقط برای مالک)
- 💾 ذخیره‌سازی دائمی با Volume — چیزی با ری‌استارت از بین نمی‌رود
- 🧱 بدون هیچ dependency کامپایلی — بیلد سریع، پایدار و تست‌شده end-to-end

> ⚠️ به‌خاطر معماری edge پلتفرم‌های ابری (TLS در لبه ترمینیت می‌شود) فقط پروتکل‌های مبتنی بر
> WebSocket/HTTPUpgrade پشتیبانی می‌شوند (نه gRPC/UDP/WireGuard) — این محدودیت پلتفرم میزبان است، نه پنل.

### ❌ چه چیزهایی عمداً پیاده‌سازی نشده‌اند (و چرا)

برای اینکه هیچ ویژگی «ادعایی و تست‌نشده» در پنل نباشد، این موارد آگاهانه کنار گذاشته شده‌اند چون
با معماری تک‌پورت Xray-core روی پلتفرم‌های ابری به‌شکل قابل‌اعتماد قابل تست/پیاده‌سازی نیستند:

- 🔒 محدودیت تعداد IP هم‌زمان (Concurrent-IP limit)
- 📱 قفل دستگاه / HWID Lock
- 🐢 محدودیت سرعت اختصاصی هر کاربر (Per-user speed limit)
- 🔌 پورت اختصاصی برای هر کاربر (چون همه از یک پورت واحد عبور می‌کنند)

به‌جای این‌ها، ارزش مشابه از طریق چند-ادمینی، گروه‌های اشتراک، گزارش فعالیت، آمار زنده سرور، نمودار
ترافیک و پشتیبان‌گیری کامل ارائه شده — ویژگی‌هایی که واقعاً تست شده و روی این معماری قابل اعتمادند.

## 🖼️ درباره «ریمارک» کانفیگ‌ها

وقتی از پنل یک کاربر جدید می‌سازید، همان **نام کاربری‌ای که تایپ می‌کنید** عیناً به‌عنوان
ریمارک (نام نمایشی) در همه کانفیگ‌های VLESS/VMess/Trojan و صفحه ساب گرافیکی همان کاربر ظاهر می‌شود —
بدون هیچ پسوند، پیشوند یا برند اضافه. اگر بعداً نام کاربری را ویرایش کنید (از صفحه جزئیات کاربر)، ریمارک
همه لینک‌ها هم بلافاصله به‌روزرسانی می‌شود.

## 🧠 معماری خلاصه

```
کلاینت (v2rayNG/...)
      │  HTTPS/WSS روی پورت 443
      ▼
  VibeNest Edge (TLS Termination)
      │  HTTP ساده + Upgrade: websocket
      ▼
   Node.js  (یک پورت واحد $PORT)
      ├── /            پنل مدیریت (وب)
      ├── /api/*        REST API پنل
      ├── /sub/:token    ساب استاندارد (base64)
      ├── /s/:token      ساب گرافیکی (QR + هدر گرادیانی)
      └── /<مسیرهای تصادفی>  →  پراکسی خام WebSocket → Xray-core (127.0.0.1)
                                     ├─ vless-in  (127.0.0.1:20001)
                                     ├─ vmess-in  (127.0.0.1:20002)
                                     └─ trojan-in (127.0.0.1:20003)
```

## 🧩 راهنمای ویژگی‌های جدید

### گروه‌های اشتراک (📦 گروه‌ها)
از منوی «گروه‌ها» چند کاربر را انتخاب و در یک گروه قرار دهید؛ یک لینک ساب واحد (`/gsub/:token`) و یک
صفحه گرافیکی گروهی (`/gs/:token`) ساخته می‌شود که کانفیگ‌های همه اعضا را یکجا نمایش می‌دهد — مناسب
برای فروش بسته‌های چند-سرویسه یا چند-دستگاهی زیر یک لینک.

### چند-ادمینی (🛡️ ادمین‌ها)
اولین حسابی که در Setup می‌سازید نقش **Owner (مالک)** می‌گیرد. مالک از صفحه «ادمین‌ها» می‌تواند
ادمین‌های دیگر اضافه/حذف کند. ادمین‌های عادی به همه‌چیز جز صفحه ادمین‌ها و پشتیبان‌گیری دسترسی دارند.

### دو استراتژی انقضا برای هر کاربر
- **تاریخ ثابت**: مثل همیشه، یک تاریخ مشخص انتخاب می‌کنید.
- **شروع از اولین اتصال کاربر**: تاریخ انقضا شمرده نمی‌شود تا کاربر برای اولین بار واقعاً وصل شود؛
  از همان لحظه، تعداد روزی که مشخص کرده‌اید شمارش معکوس می‌شود. مناسب برای فروش بسته‌هایی که
  مشتری هر وقت خودش خواست فعال‌شان می‌کند.

### آمار زنده سرور و نمودار ترافیک
داشبورد هر ۵ ثانیه آمار CPU/RAM/دیسک را به‌روزرسانی می‌کند (بدون رفرش صفحه) و نموداری از مجموع
مصرف ترافیک ۱۴ روز اخیر نمایش می‌دهد.

### گزارش فعالیت (⏱️ فعالیت‌ها)
هر اکشن مهم (ورود، ساخت/ویرایش/حذف کاربر یا گروه، تغییر تنظیمات، ری‌استارت Xray و…) با زمان و نام
ادمین انجام‌دهنده ثبت می‌شود.

### پشتیبان‌گیری و بازیابی
از صفحه تنظیمات (فقط مالک) می‌توانید کل وضعیت پنل (کاربران، گروه‌ها، ادمین‌ها، تنظیمات) را به‌صورت
یک فایل JSON دانلود یا از یک فایل قبلی بازیابی کنید — مفید برای مهاجرت بین سرویس‌ها یا بکاپ دوره‌ای.

### خاموش/روشن سراسری هر پروتکل
از تنظیمات می‌توانید VLESS/VMess/Trojan را کلاً خاموش کنید (مثلاً اگر یکی از آن‌ها در شبکه‌ای
فیلتر شد)، بدون این‌که لینک‌های ساب کاربران نیاز به تغییر داشته باشند.

## 🚀 روش ۱ (پیشنهادی): نصب روی VibeNest — فقط فورک + لینک ریپازیتوری

> کل مراحل زیر کمتر از ۳ دقیقه طول می‌کشد و هیچ تنظیم دستی‌ای لازم ندارد.

### ۱. فورک ریپازیتوری
ریپازیتوری را در گیت‌هاب خودتان **Fork** کنید (یا همین پوشه را push کنید).

### ۲. ساخت پروژه در VibeNest
1. وارد حساب VibeNest شوید → **New Project → Deploy from GitHub repo**.
2. ریپازیتوری همین پنل را انتخاب کنید.
3. تنظیمات بیلد را به این شکل بگذارید (اگر خودکار تشخیص داده شد، دست نزنید):
   - **Build pack:** `docker-compose`
   - **Compose file:** `/docker-compose.yml`
   - **Internal port:** `8080`
4. دکمه **Deploy** را بزنید.

VibeNest به‌صورت خودکار:
- متغیرهای داخل `.env.example` را می‌سازد (`APP_URL` با آدرس نهایی HTTPS پروژه و `ADMIN_PASSWORD` با یک رمز تصادفی قوی)،
- ولوم `panel_data` را برای مسیر `/data` می‌سازد (داده‌ها بعد از هر ری‌دیپلوی باقی می‌مانند)،
- و سرویس `app` را روی پورت داخلی `8080` منتشر می‌کند.

> اگر دکمه بیلد به‌جای Compose روی **Dockerfile** باشد هم مشکلی نیست: همین `Dockerfile` ریشه پروژه
> بیلد می‌شود. فقط یادتان باشد یک Volume دستی روی مسیر `/data` اضافه کنید و `Internal port` را `8080` بگذارید.

### ۳. ورود به پنل
1. آدرس تولیدشده (مثلاً `https://my-panel.vibenest.net`) را باز کنید.
2. در صفحه ورود:
   - **نام کاربری:** مقدار `ADMIN_USERNAME` (پیش‌فرض `admin`)
   - **رمز عبور:** مقدار `ADMIN_PASSWORD` که در بخش Variables پروژه VibeNest قابل مشاهده است.
3. همین! داشبورد بالا می‌آید و هسته Xray هم تا چند ثانیه بعد وضعیت «در حال اجرا» می‌گیرد.

> اگر `ADMIN_PASSWORD` را خالی بگذارید، پنل مثل قبل اولین بار صفحه **Setup** را نشان می‌دهد تا خودتان
> حساب مالک را بسازید — هیچ خطایی رخ نمی‌دهد.

### ۴. ساخت اولین کاربر
منو → **کاربران → + کاربر جدید**. نامی که تایپ می‌کنید، دقیقاً همان ریمارک کانفیگ‌هایش خواهد بود.
سپس از صفحه کاربر، **صفحه گرافیکی اشتراک** را باز کنید یا QR هر کانفیگ را اسکن کنید.

### ۵. دامنه اختصاصی (اختیاری)
اگر در VibeNest یک Custom Domain وصل کردید، نیازی به هیچ تغییری در کد نیست؛ پنل دامنه جدید را
از روی هدرهای درخواست تشخیص می‌دهد. برای ثابت‌کردن آن می‌توانید متغیر `PUBLIC_DOMAIN` را ست کنید
یا از صفحه **تنظیمات → دامنه** واردش کنید.

## ✅ چرا این نسخه روی VibeNest بدون خطا بالا می‌آید؟

| ریسک رایج هنگام دیپلوی | کاری که این نسخه انجام می‌دهد |
|---|---|
| بیلد به‌خاطر دانلودنشدن هسته Xray fail می‌شود | دانلود Xray در زمان بیلد **اختیاری** است؛ اگر شکست بخورد بیلد موفق تمام می‌شود و برنامه موقع اجرا خودش هسته را دانلود می‌کند |
| پلتفرم به‌جای Dockerfile با بیلدر خودکار بیلد می‌کند | `package.json` (`npm start`) و `Procfile` هم آماده‌اند؛ هسته Xray در زمان اجرا دانلود می‌شود |
| مسیر `/data` قابل نوشتن نیست (کانتینر non-root) | به‌صورت خودکار به مسیر `./data` داخل پروژه fallback می‌کند و کرش نمی‌کند |
| دامنه در لینک کانفیگ‌ها اشتباه است | دامنه از `APP_URL` یا هدر `x-forwarded-host` تشخیص داده و ذخیره می‌شود |
| کوکی ورود پشت HTTPS کار نمی‌کند | `trust proxy` فعال است و کوکی بر اساس `x-forwarded-proto` با/بدون `Secure` ست می‌شود |
| سرویس در هِلث‌چک fail می‌شود | مسیر `/health` همیشه ۲۰۰ برمی‌گرداند، حتی اگر هسته Xray هنوز بالا نیامده باشد |
| یک خطای غیرمنتظره کل سرویس را می‌خواباند | `uncaughtException` / `unhandledRejection` مدیریت شده‌اند و خطای Xray هرگز پنل را آفلاین نمی‌کند |

## 🖥️ روش ۲: نصب روی VPS / سرور شخصی با Docker

```bash
git clone https://github.com/USERNAME/REPO.git
cd REPO
chmod +x install.sh
./install.sh
```

یا مستقیماً با Compose:

```bash
cp .env.example .env     # ADMIN_PASSWORD را پر کنید
docker compose up -d --build
```

سپس پورت `8080` را پشت Nginx/Caddy با TLS قرار دهید (کانفیگ‌ها روی پورت 443 و `security=tls` ساخته می‌شوند).

## ⚙️ متغیرهای محیطی (Environment Variables)

همه اختیاری هستند — پنل بدون تنظیم هیچ‌کدام هم بالا می‌آید.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `APP_URL` | — | آدرس عمومی پروژه؛ **VibeNest خودش پر می‌کند** |
| `ADMIN_USERNAME` | `admin` | نام کاربری مالک پنل |
| `ADMIN_PASSWORD` | — | رمز مالک پنل؛ VibeNest یک مقدار امن تولید می‌کند. اگر خالی باشد، صفحه `/setup` نمایش داده می‌شود |
| `PUBLIC_DOMAIN` | خودکار | override دستی دامنه (مثلاً دامنه اختصاصی) |
| `PORT` | `8080` | پورتی که پنل روی آن گوش می‌دهد |
| `HOST` | `0.0.0.0` | اینترفیس شنود |
| `DATA_DIR` | `/data` | مسیر ذخیره‌سازی دائمی (در صورت نبود دسترسی، به `./data` برمی‌گردد) |
| `JWT_SECRET` | تصادفی و خودکار | کلید امضای نشست ادمین |
| `XRAY_VERSION` | `v26.9.9` | نسخه هسته Xray |
| `XRAY_API_PORT` | `10085` | پورت داخلی API آمار Xray (فقط 127.0.0.1) |
| `XRAY_INBOUND_BASE_PORT` | `20000` | پایه پورت‌های داخلی inboundهای Xray |

## 🖥️ اجرای محلی (اختیاری، برای تست/توسعه)

```bash
npm install
DATA_DIR=./data PORT=3000 ADMIN_USERNAME=admin ADMIN_PASSWORD=change-me-123 npm start
```

سپس `http://localhost:3000` را باز کنید. (هسته Xray در اولین اجرا خودکار دانلود می‌شود.)

## 🔐 نکات امنیتی

- رمز عبور ادمین را قوی انتخاب کنید و هر چند وقت از صفحه تنظیمات تغییر دهید.
- لینک **صفحه گرافیکی اشتراک** (`/s/:token`) را فقط با همان کاربر به اشتراک بگذارید.
- اگر یک کاربر نشت پیدا کرد، از دکمه «ساخت مجدد UUID / لینک ساب» در صفحه همان کاربر استفاده کنید.
- Volume مسیر `/data` را حذف نکنید — همه کاربران، گروه‌ها و تنظیمات داخل آن هستند.

## 🩺 عیب‌یابی سریع

| مشکل | راه‌حل |
|---|---|
| بیلد روی VibeNest fail می‌شود | Build pack را روی `docker-compose` و Compose file را `/docker-compose.yml` بگذارید؛ Internal port = `8080` |
| سرویس بالا می‌آید ولی صفحه باز نمی‌شود | Internal port باید دقیقاً `8080` باشد (همان مقدار `expose` در Compose) |
| با هر ری‌دیپلوی کاربران پاک می‌شوند | ولوم `panel_data` روی `/data` باید حفظ شود (در حالت Dockerfile، دستی اضافه‌اش کنید) |
| رمز ورود را نمی‌دانم | در VibeNest → Project → Variables → مقدار `ADMIN_PASSWORD` را Reveal کنید |
| کلاینت وصل نمی‌شود ولی پنل بالاست | در لینک کانفیگ باید `security=tls` و پورت `443` باشد (نه پورت داخلی) |
| هسته Xray «متوقف» نشان می‌دهد | چند ثانیه صبر کنید (در حال دانلود خودکار است) یا صفحه تنظیمات → «وضعیت هسته Xray» را ببینید |
| دامنه در کانفیگ‌ها اشتباه است | یک‌بار پنل را با دامنه درست باز کنید، یا `PUBLIC_DOMAIN` را ست کنید |
